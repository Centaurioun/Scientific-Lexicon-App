## Product and architecture
TermForge is working name. Long-term local-first scientific/academic language intelligence, one concept-centric EN/TR database; English extraction/UI first; Turkish later. Three separate logical libraries scientific termbase, Academic Phrasebank, Editorial & Style (not implemented beyond termbase). Not full CAT/TM/translation engine, SaaS, microservices, mandatory AI, PDF OCR or external server. Current Next.js App Router React TypeScript modular monolith, browser-only text and Dexie IndexedDB; Zod runtime schemas, Vitest and Playwright. Domain/application/adapters/UI separated; no server text/database, telemetry or remote models. SQLite optional fallback if G4 host fails; not current product.
Canonical concept and expression IDs independent, multiple forms per concept, same spelling different concepts (PD), partial EN/TR and shared/undetermined explicit. Unicode raw case exact, half-open UTF-16 source slices, group identical span once, nested distinct; scientific boundaries L/M/N/_/+ and provisional hyphen. Aho exact recognition separate from unknown discovery; Wink public NLP feature API; no invented translations or confidence, acceptance/user-confirmed not independently verified. All writes through immutable ChangeSet SHA-256 payload and approval, revision CAS, batch replay/conflict, atomic Dexie across stores; protected verified text/language/concept, no direct put/delete/merge. Full snapshot JSON backup separate from presentation TXT/MD/CSV/JSON, empty-target atomic restore only, history/digest integrity, CSV injection safety. Session-only source default, explicit retention/delete removes document/runs/source pointers; downloaded backups outside app control. No raw text audit/log/URL/network. Canonical backup v1 unchanged. Read [master design](../architecture/MASTER-DESIGN-BASELINE-v1.0.md), [S1 contracts](../specifications/S1-IMPLEMENTATION-CONTRACTS-v0.1.md), [engineering workflow](../decisions/ENGINEERING-DECISION-WORKFLOW.md).
