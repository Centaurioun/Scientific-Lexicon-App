## 1. Product and non-goals
A local-first scientific and academic language intelligence platform. English extraction initially, EN/TR data and lookup from day one, Turkish NLP/UI later. Dentistry/periodontology and medicine are first evaluation domains, not hardcoded product limits. First useful slice: input English text -> unknown and known candidate discovery -> original context -> human review -> durable bilingual concept/expressions -> search -> export/backup. Separate scientific termbase, academic phrasebank (collocations/rhetorical functions) and editorial/style library share infrastructure, not semantic identity. Do not build full CAT/TM, translation engine, PDF OCR, SaaS, billing, sync, vector DB, microservices or plugin marketplace now. No real terminology or manuscripts seeded or in public Git. No mandatory AI, account, backend or Python for core.

## 3. Architecture and boundaries
Modular monolith; UI -> use cases -> domain and narrow ports -> infrastructure adapters. Domain must not import React, Next.js, Dexie, Wink, Aho package or vendor types. Organize by feature with shared identity/validation/provenance only where used. Proposed modules: terminology, extraction, review, change gateway, storage, document input, exchange. Future separate phrasebank, editorial, preparation, enrichment, sources, audit, maintenance. Document future seams now, implement only needed interfaces and real pages, no empty service/route shells. Browser execution for private text/storage; heavy matching/model work in worker when measured/available, no server transmission. No external service or network during core processing; never expose API secrets client-side. If browser host cannot support local processing, stop and report rather than silently send data to server. App origin explicit; preview is disposable.

## 4. Canonical semantics
Concept: opaque stable ID, revision, lifecycle, type, domain/category links; one or more expressions; partial languages allowed. Expression: independent ID, concept ID, original/display text, language tag (en/tr with regional variants) or explicit shared/undetermined use field (not fake BCP47 code), expression role, revision, source and verification assertions. Multiple forms same concept; same surface different concepts. No global text uniqueness; duplicate candidate within same concept/language/form requires review. Preserve aliases separately, including acronym, orthographic, morphological, British/US, historical/nonpreferred. Distinguish semantic exact/near synonym, abbreviation expansion, alternative translations and preferences. Never merge gene/protein, disease/finding or numbered molecular identity without evidence. Preferences scoped by profile, language, domain/project; independent of validity. Concept relations typed broader/narrower/related/part-of with evidence, reject self and hierarchy cycles. Definitions separate language-specific records. ExternalMapping authority+release+external ID+relation, separate from internal ID. MeSH descriptor/concept/term/tree distinctions and version retained; MeSH entry terms not automatically synonyms. Bilingual domain hierarchy, semantic categories, tags and collections distinct; multiple links, primary optional, unclassified valid. Basic metadata for first slice; rich fields added with migrations when used.
Source registry: authority/URI/version/license/retrieval/provenance; Evidence points to record+field/value or relation, source/location and allowed excerpt. VerificationAssertion targets exact value/revision, actor/method/time/evidence; confidence, agreement, support, review and preference separate. Unknown vs not applicable vs missing explicit. Never invent missing EN/TR counterpart; never mark model output verified. A confirmed expression may coexist with unverified proposed translation.
Document/run: original text, parser/algorithm/index/rule versions, optional local retention policy; Occurrence = original half-open UTF-16 span, exact source slice, document/run, candidate IDs, resolution status. Group identical span once, preserve nested spans, unresolved not counted as resolved, distinguish unique concepts/expressions/occurrences. Reruns distinct, no accidental double-count across runs. Review statuses proposed/accepted/rejected/ambiguous, scoped ignore-once or rules later; accepted discovery does not automatically imply independent source verification. Keep all source spans.
Phrasebank later: Phrase/Variant, language, rhetorical function, section/register/grammatical pattern/collocation and restrictions, translations/alternatives/evidence. Editorial rules separate. et al. not scientific term by default; cross-links where meaningful.

## 5. Scientific matching and discovery policy (proposed v1)
Raw text immutable. Exact case-sensitive literal registered form first; explicit aliases only, no blanket casefold/NFKC/diacritic removal or punctuation deletion. Normalize search keys separately, with policy version; any future canonical Unicode matching must map offsets to raw text. Trim exterior whitespace and collapse clearly redundant ordinary spaces in staged display value only, preserve raw, flag repeated hyphen and punctuation for contextual review; preserve comma in 2,4-dinitrophenol and period in et al. Case matters p53/P53, Turkish I/İ/ı, gene/protein symbols. Base exact-match boundary Unicode L/M/N/underscore/plus adjacent; hyphen treated as provisional separator only: x-TNF-α may yield candidate, not automatic concept resolution; HLA-B vs HLA-B27 and CD4+ vs CD4++ distinguished. Do not assert universal chemical/inflection boundary; extend typed rules with fixtures. Group same-span candidate IDs; retain nested periodontal ligament and periodontal ligament-derived stem cells. R20 inclusive ends convert to half-open UTF-16; assert exact raw slice. Cache compiled matcher by library revision and policy version; invalidate on accepted changes, never use stale index silently, cancel or rebuild in worker for large dictionaries. Compare simple literal scan at small sizes; no arbitrary threshold without measurements.
Pipeline: parse -> sentence/section-aware raw spans -> known literal matches and independent candidate generation -> candidate union/dedup spans -> explainable features/ranking -> possible concept resolution -> user review -> novelty filter/output. Known terms not deleted from input; unknown discovery with empty dictionary required. Wink token/POS/sentences using public API, raw offsets validated; explicit symbol-aware candidates, eponyms, internal function words, single/multiword, statistical/methodological/nomenclature, scientific adjectives and verbs where appropriate. Use general-word frequency and morphology as soft signals; no blanket rejection of names, numbers, ordinary words, verbs. Avoid crossing sentences/document boundaries. Initial ranking transparent and conservative; no unmeasured confidence probability. Later TF/DF, C-value/NC-value, Weirdness, TF-IDF, morphology and optional biomedical adapter evaluated on common holdout, not all methods mandatory. Optional AI validates uncertain candidates or separately proposes missed terms only with source span and review.

## 6. Write and storage integrity
All canonical mutations through one application use case with strict runtime validation. Staging/candidate/review packages never direct master writes. Explicit approved proposal includes stable batch and operation IDs, expected revisions, canonical digest over immutable payload and approval bound to that payload. Compute digest before transaction; recheck persisted idempotency, expected versions, ID collision, references, protected fields and approval inside transaction. Same ID+same digest returns prior outcome without mutation; same ID+different digest conflict; stale rejection; all-or-nothing data and audit commit, never return success on abort. New ID cannot overwrite existing row; update requires exact revision. Any verified value change requires separate explicit authorized replacement review preserving previous assertion/history; ordinary import/AI cannot change it. Deletion/merge reviewed with references and undo via compensating change, no blind destructive action. IndexedDB has no automatic FK constraints; enforce in adapter. Consistent snapshot across stores in one read transaction; validated versioned JSON, referential integrity and unique IDs, explicit counts and preview. First restore only to empty isolated library; refuse overwrite existing library until safe replacement/migration strategy tested. Backup before risky change, portable file download and verify; browser persistence request and quota warning visible, no guarantee, no silent in-memory fallback. No real data in preview; stable deployment/origin and restart tests before real use. Schema migration versioned, atomic or fail closed, blocked connections visible. Keep personal data outside public Git and telemetry.

## 7. Import, AI, sources, interchange and QA roadmap contracts
Data preparation later: raw TXT/MD/CSV/XLSX/DOCX/JSON/TBX/TMX -> mapping/cleaning -> isolated staging -> strict canonical schema -> validation, duplicate/conflict review -> preview -> approval -> transaction/checkpoint. OpenRefine standalone for legacy lists; Anchovy patterns, no whole app. Missing cells null/absent per schema; not dash/N/A as data by default. Idempotent chunks with clear partial/whole-batch semantics, audit/rollback guards. JSON rich canonical exchange, keyed CSV/TSV/XLSX views with loss report, TXT/MD alphabetical or frequency. Protect spreadsheet formula injection; safe XML parsing (no external entities/network), dialect/version. TBX for concept termbase (Termate/Terminologue/Anchovy references). TMX/optional XLIFF for phrase mining, not full CAT or segment-to-term import; Trados proprietary SDLTB/SDLTM via standard export. 
External sources later: MeSH/SPECIALIST and approved OBO sources, Turkish TDK/TÜBA/TBT, permitted bilingual corpora, source-specific rights and provenance; never mandatory UMLS or automatic verified seed. TermitUp source adapter pattern. Open Phrasebank/Elsevier OA CC-BY v2 offline mining with provenance; Manchester/BAWE and unclear datasets HOLD pending rights, no raw corpora public. Keep clinical/medical personal texts private. 
Enrichment later: missing field tasks, optional provider adapters, independent blind review and standardized external AI exchange without API. Export minimum scoped task/record/base revision/schema version + response instructions; reimport patches only, validate IDs/revision/source, compare independent votes and evidence separately; 3/3 agreement not truth. Bulk approval with sampling and conflict queue, no automatic verified writes. AI consent, no implicit uploads, no credentials in client or git. 
Writing and translation later: relevant concept glossary, EN/TR profiles and contextual preferences, terminology/case/abbreviation/collocation/phrase repetition/editorial audit, bilingual source/target alignment and missing/mismatched concepts. Report non-destructive findings with location and rationale, never silently rewrite or equate rhetorical alternatives; no guarantee of scientific or translation correctness. Maintenance later: quality inspector, duplicate suggestions, safe cleanup/history, analytics and advanced backup; basic protection early.

## 11. Approaches considered and decision rationale
These are the alternatives already discussed across four brainstorming rounds, the ecosystem research and P0; no claim that the owner approved every technical detail yet.

| Approach | Advantages | Trade-offs | Disposition |
|---|---|---|---|
| Fork TermKit or Terminologue | Existing concept model/editor and interchange | Inherits different stack, pre-alpha or legacy behavior, migration burden, mismatched scientific/phrasebank scope | Do not fork; selectively reference the model, review and editor patterns |
| Custom local-first Next.js/TypeScript modular monolith using small qualified dependencies | AI Studio workflow fit; offline English analysis; explicit concept and write boundaries; portable | Must implement scientific candidate grammar and transactional domain policy; origin/eviction risk | Recommended; conditional on S0 and selected-only dependency gates |
| Python/server-first or desktop SQLite from outset | Rich biomedical tooling and mature relational storage | Additional runtime, deployment and privacy complexity; less suited to chosen initial builder | Fallback if browser-first path fails real-data readiness; optional Python later |

Within the recommended approach use Dexie over native IndexedDB boilerplate, R20 over broken R21 1.0.1, and Wink features over a mandatory remote model. The P0 results support those candidates but do not establish production quality. No need to reopen the alternatives without material new evidence.

## 12. Initial product contract and completion boundaries
S0 is a disposable, synthetic compatibility experiment, not a product. S1 is a single useful vertical slice delivered through independently reviewable increments. The exact file layout, runtime schema and tasks belong in the post-approval Writing Plans, not this product design.

| Increment | Working deliverable | Required observable behavior |
|---|---|---|
| S0 | Disposable AI Studio probe | Actual package/worker/storage operations, logs and code export; no product library or private inputs |
| S1a | Foundation and bilingual library | Empty on first use; create/edit a concept with one or more independent forms in EN/TR/shared use; search; explicit review and safe transaction; reload; minimal error states |
| S1b | Local English extraction and review | Paste/TXT input; independent unknown discovery and known matcher; context and original spans; known-form, possible new form, new candidate and ambiguous/unresolved distinctions; approve/create/link or reject without deleting known substrings |
| S1c | Portable outputs and recovery | Filter/sort current run and library; TXT/MD/CSV/JSON exports, separate complete versioned backup; preview/validate and restore only into empty target; verify no partial writes on invalid input or failed commit |

S1a/S1b may use synthetic fixtures only; S1c closes the first working slice. No real library intake merely because S1 is complete. S2 enhances scientific quality and document ingestion; S3 enables strict bulk preparation and import only when real-data gate passes. Future modules are not requirements for S1. No navigation item claiming unsupported capabilities. UI should provide readable source/candidate review, keyboard-accessible controls, clear loading/empty/error states, and separate concept and expression views; styling is builder discretion within accessible desktop-first English UI. No additional design mockup approval needed unless a substantive workflow change is proposed.

### S1 decisions proposed by the designer
- A concept with one valid expression is sufficient; create it and its first expression atomically. Avoid orphan concepts/expressions. Shared/undetermined is an explicit use designation, not a fabricated language code. No global unique surface constraint.
- Default discovery is a candidate list, never a verified scientific dictionary. A human accepting a candidate into the library does not automatically create independent evidence or a source-verified translation. No automatic concept merge, destructive bulk delete or inferred translation in S1. An exact unique registered form is a known-form association; context-sensitive semantic resolution is distinct. An unknown surface is not necessarily a new concept.
- Raw scientific text stays browser-local. Default document retention is session-only; persistent retention of document/context is explicit opt-in, with clear retention/delete controls. Saving a concept does not require saving a manuscript. When source text is not retained, do not claim durable exact context evidence; retain only permitted metadata and explicitly indicate unavailable source/context. Retain exact occurrence and spans for current run; cross-document statistics only for deliberately retained evidence. Never transmit manuscripts to a server/model, third-party analytics or logs in S1.
- Use a single versioned canonical schema, one controlled mutation path and one repository abstraction. The S1 record set contains only fields needed by real use cases, but stable IDs, record revisions, provenance/verification distinction and references are not deferred. New forms are independent records, not free-text aliases. Precise field names/validation/canonical serialization and transaction table sets will be fixed in the approved implementation plan.
- Initial export is a user-selected presentation of concepts or expressions (TXT/MD/CSV) or structured records (JSON), with selected scope and deterministic alphabetical/frequency order. Presentation exports are not backups. Backup contains the entire persisted canonical library, applicable history, metadata and format/schema version with validation; excludes derived caches and session-only documents. Rebuild caches after restore. Make CSV cells safe for spreadsheet interpretation without modifying stored forms.
- Initial write commands may create, edit, accept/reject and link via explicit review; merges/deletions requiring cascade or replacement of verified scientific assertions are not enabled until their own safety tests. Verified value replacement remains an explicit reviewed operation, not ordinary editing. An unsupported operation fails clearly, never silently succeeds.

## 13. Acceptance gates by risk and stage
| Gate | Required evidence | Consequence of failure |
|---|---|---|
| G0 design | Owner approves exact final candidate and scope, then Writing Plans produces reviewable task plan | No product implementation |
| G1 selected dependencies | Exact registry artifacts, lock/integrity, selected-only transitive rights/NOTICE and security review; no R21 or unnecessary dependencies | Do not adopt blocked component; propose minimal fallback |
| G2 AI Studio compatibility (S0) | Actual selected project runtime, Next.js/React host, public package APIs, local browser execution, worker support or measured safe fallback, synthetic transaction/abort/reload and export path; record origin and persistence response | Stop/diagnose; no silent server processing or framework change; present fallback if host cannot meet privacy/integrity |
| G3 core correctness (S1) | Real application hard assertions for first record, many expressions, same string different concepts, missing language, exact UTF-16 source spans, known/new ambiguity and empty-dictionary discovery; same-payload replay, changed payload conflict, stale edit, duplicate IDs, orphan refs, approval binding, all write paths protected, abort fail closed; consistent snapshot and invalid restore without any mutation | No feature completion claim; fix failing path |
| G4 real data readiness (before personal imports) | Stable target origin, browser restart, actual simultaneous tab race, realistic migration, blocked upgrade, quota/denial, portable restore into independent empty origin, source retention/delete policy, backup drill, scale/capacity and rollback; source rights for external data | Synthetic use only; if origin/durability unsafe, evaluate SQLite/desktop or other approved local-first path |
| G5 scientific quality (S2+) | Independent annotated EN documents, held-out spans/concepts, baseline comparison, precision/recall/F1, unknown and nested term recall, false rejection, workload and performance; set quantitative thresholds after baseline/owner review | Do not claim validated scientific extraction or use automatic acceptance; keep reviewed candidates |
| G6 later modules | Specific source license/version, import safety, external AI consent/patch validation and separate field evidence; bilingual gold for translation QA, Turkish holdout for TR extraction | Keep feature disabled/deferred; no invented accuracy/verification |

The gates are not a demand to solve all later research before a synthetic prototype. G1 must precede actual dependency integration, G2 precedes product build in that environment, G3 precedes S1 acceptance, G4 precedes real data, G5/G6 precede their respective quality/feature claims. Negative persistent-storage grant by itself is not failure of G2; it is an explicit G4 risk. No numeric performance target is fabricated from six labels or synthetic matcher microbenchmarks. Record PASS/FAIL/BLOCKED/NOT TESTED, environment, commands, raw results and limitations.
