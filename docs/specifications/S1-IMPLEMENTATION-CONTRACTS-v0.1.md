# S1 implementation contracts v0.1 — planning decisions
Status: proposed engineering details under approved v1.0. Plan approval covers these details; no product code exists. S0 outcome may force revision; material changes require owner approval. This is the single cross-plan interface authority. Type names below are exact planned TS names; runtime validators in src/domain/schema.ts derive TS types from a single schema authority (Zod candidate). All persisted records JSON-safe; timestamps UTC ISO 8601, IDs opaque UUIDs generated with crypto.randomUUID(), revisions nonnegative safe integers. No undefined, NaN, Infinity, Date objects or arbitrary keys in persisted DTOs.

## Files and records
- src/domain/schema.ts: Concept { id, revision, createdAt, updatedAt }; Expression { id, conceptId, revision, text, language: LanguageUse, role: ExpressionRole, createdAt, updatedAt }; LanguageUse = {kind:"language",tag:"en"|"en-US"|"en-GB"|"tr"} | {kind:"shared"} | {kind:"undetermined"}; ExpressionRole = "preferred"|"alternative"|"abbreviation"|"acronym"|"orthographic"|"morphological"|"historical"|"nonpreferred"|"unspecified". Role "preferred" is a user designation, not scientific verification. Concept has no mandatory domain/category in S1; future labels via migration. No arbitrary synonym equality.
- VerificationAssertion { id, expressionId, field:"text", value, recordRevision, kind:"user-confirmed", actor:"local-user", assertedAt }; user-confirmed is an explicit owner assertion, not source/expert verified. S1 acceptance alone creates no assertion. Protected if assertion binds current value; ordinary edit to text prohibited. Any other field change that would invalidate assertion binding (language or concept identity) rejected; no replacement/delete command in S1. Assertions remain auditable; record revision change does not erase existing protection. Provenance { id, expressionId, kind:"manual"|"reviewed-candidate", createdAt, source: null | {documentId,runId,start,end} }; non-null source requires retained matching document/run/occurrence; session-only review persists kind without source pointer or context. No fake source evidence.
- RetainedDocument { id, text, title, createdAt }; RetainedRun { id, documentId, algorithmVersion, libraryRevision, createdAt, occurrences: Occurrence[] }; Occurrence { id,start,end,surface,expressionIds:string[],conceptIds:string[],state:"known-form"|"new-candidate"|"possible-new-form"|"ambiguous",resolvedConceptId:string|null }. For retained historical associations, IDs must exist when committed; no deleting library concepts in S1. A span is grouped once; two different spans may overlap. A manual resolution is a user decision, not source verification. Unknown/ambiguous not counted resolved unless explicitly linked. No document persistence without explicit consent. Deleting a retained source removes document+its runs and clears corresponding provenance.source in one approved change; preserve other metadata and concept records. Audit and idempotency metadata must never contain raw document text, raw excerpt, or reversible document content after deletion.
- src/domain/changes.ts: ChangeOp discriminated union with opId for createConcept(concept,firstExpression,provenance), addExpression(expression,provenance,expectedConceptRevision), editExpression(id,expectedRevision,text,language,role), assertExpression(id,expectedRevision,assertion), retainDocument(document,run), deleteRetainedDocument(id); manual review accept/create/link uses createConcept/addExpression or retainDocument, reject is session-only. No generic put, merge, delete expression/concept, or verified replacement. For retainDocument use explicit separate consent; for delete use explicit confirmation. New concept and expression revisions start at 0; createConcept and first form atomic; addExpression bumps concept revision, edit/assert bump expression revision and associated concept revision; global library revision increments on every successful persisted changeset. 
- ChangePayload { schemaVersion:1, batchId, baseLibraryRevision, ops:ChangeOp[] }; Approval { batchId,digest,actor:"local-user",approvedAt }; ProposedChange { payload,digest,preview: string[] }; ApplyResult discriminated {status:"applied"|"replay",revision} | {status:"conflict"|"stale"|"invalid"|"protected"|"aborted"|"unavailable",reason:string}. preview derived from actual payload; approval generated only from explicit user action on immutable proposal. Approval digest binds entire payload, not a password/auth boundary. Canonical JSON recursively sorts object keys, preserves array order, rejects non-JSON values; SHA-256 UTF-8 digest lowercase hex via Web Crypto computed before transaction. Payload copied/frozen, revalidate approval digest/shape and persisted checks inside transaction; no unrelated async work inside transaction. Same batchId+digest returns recorded revision, same ID+different digest conflict, then check base revision and expected record revisions. Store batchId,digest,appliedRevision only (no payload). Audit { id,batchId,opId,kind,recordIds,actor,approvedAt,appliedRevision } without sensitive source text. Audit is not a full before/after reversible log in S1; full semantic undo for imports/merge later. Record operation ID uniqueness across batches and within payload. All writes atomic with meta revision and audit/batch. Return applied only after transaction completion; unexpected errors mapped aborted/unavailable, never success. 
- src/domain/repository.ts: LibrarySnapshot { schemaVersion:1,libraryRevision, concepts,expressions,assertions,provenance,documents,runs,batches,audit } each array sorted by stable ID (batches by batchId). LibraryRepository interface snapshot():Promise<LibrarySnapshot>, apply(proposal:ProposedChange,approval:Approval):Promise<ApplyResult>. RecoveryRepository extends LibraryRepository with restoreEmpty(backup:BackupEnvelope,approval:RestoreApproval):Promise<ApplyResult> in S1c only; earlier adapters need not implement recovery. BackupEnvelope {format:"termforge-backup",version:1,snapshot:LibrarySnapshot,digest:string}; RestoreApproval {digest,actor:"local-user",approvedAt}. Digest over canonical snapshot; check full validation and referential/history coherence before write, recheck truly empty target (all stores, libraryRevision=0) inside single transaction. Preserve revisions/history exactly, exclude session docs/derived caches. Restore is separate approved mutation in same application gateway, no direct UI/storage calls. 
- src/adapters/storage/dexie-library.ts: object stores meta, concepts, expressions, assertions, provenance, documents, runs, batches, audit; Dexie schema version 1, compound indexes only as needed. Atomic transaction over all affected stores, snapshot one read transaction across stores. No silent memory fallback. IDs use add for creates and revision-checked updates, no blind put. Initialize meta revision 0 without seed. Read-time validation for corrupted state, fail closed.
- src/application/library.ts: listLibrary():Promise<LibrarySnapshot>; findExpressions(snapshot,query):Expression[] (case-sensitive literal text substring, empty query all, stable sort by text then id; never mutates identity); proposeChange(snapshot:LibrarySnapshot,payload:ChangePayload):Promise<ProposedChange>; approveChange(proposal:ProposedChange):Approval only at explicit UI action; applyChange(repo,proposal,approval):Promise<ApplyResult>. Avoid persisting raw source context in proposal journal. 
- src/domain/extraction.ts: Span {start,end,surface}; Token extends Span {pos,sentenceId}; NlpEngine.analyze(text):Promise<Token[]>; RegisteredMatcher.match(text,expressions):Promise<Occurrence[]>; CandidateGenerator.generate(text,tokens):Span[]; ExtractionRun {id,text,algorithmVersion,libraryRevision,occurrences}; analyzeText(text,snapshot,nlp,matcher):Promise<ExtractionRun>; selectCandidates(run,filter):Occurrence[]; ReviewIntent "create-concept"|"link-form"|"reject"|"resolve-existing"; review constructs ChangePayload using current snapshot and explicit user choice, no direct write. Reject/current-run resolution session state. 
- Exact match boundary: adjacent Unicode letter/mark/number/underscore/plus disallows literal match; hyphen is provisional separator, so x-TNF-α may match known form but not resolve scientific identity. Convert inclusive R20 ends to half-open UTF-16; verify original slice; group same span all IDs, retain nested spans. Exact original case only. Cache per libraryRevision+boundary policy; discard stale response before displaying/applying. Simple indexOf fallback uses identical boundary semantics. No unknown-term detection via dictionary alone.
- Initial candidate grammar: within one sentence, contiguous POS spans of 1–8 tokens beginning ADJ/NOUN/PROPN and ending NOUN/PROPN, with internal ADJ/NOUN/PROPN/ADP/DET; plus bounded raw scientific-symbol token spans (letter/digit, hyphen, Greek, +, slash) with at least one letter and digit or Greek/symbol marker; preserve scientific names and eponyms, no numeric-only candidate. Retain single nouns and nested spans; exact slice, no cross-sentence spans. Wink public POS mapped to canonical categories; if offsets cannot reconstruct, fail rather than fabricate. Candidate rule version "s1-grammar-1". Sort by first occurrence then longer span then stable ID, not pseudo-confidence. Unknown candidate classification unless explicit user proposes a new form linked to existing concept; do not guess synonymy. Later S2 ranker quality tests.
- src/application/exchange.ts: ExportSelection {scope:"library-concepts"|"library-expressions"|"current-run",sort:"alphabetical"|"frequency",language:"all"|"en"|"tr"|"shared",includeKnown:boolean}; ExportRow {id,conceptId:string|null,text,language:string,frequency:number|null,state:string}; selectExportRows(snapshot,run|null,selection):ExportRow[]; formatExport(rows,format:"txt"|"md"|"csv"|"json"):string; createBackup(snapshot):Promise<BackupEnvelope>; validateBackup(input:unknown):Promise<BackupEnvelope>. Concepts select one display form per filtered language (preferred first, then deterministic text/id), no inferred translation; current run groups identical exact surface/state/association set, preserves unresolved as null conceptId. Frequency current run count; library frequency only from retained resolved occurrences, missing = null (not zero), null last. Alphabetical deterministic Unicode code-point or documented binary UTF-16 order (initial UTF-16 code-unit comparator), tie id; no locale-dependent default. CSV quote/escape and prefix apostrophe for formula-leading =,+,-,@,tab,CR/LF after leading whitespace; stored forms untouched. JSON presentation {format:"termforge-export",version:1,rows}, never accepted as backup. TXT one line per row, escape control newlines; Markdown table escape pipes/backslashes and linebreaks. Use UTF-8 file download via Blob; no network.
